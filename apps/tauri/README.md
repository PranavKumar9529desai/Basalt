# Basalt — Tauri app layer

This is the runnable desktop application. It is a thin React frontend over a
Rust backend (`src-tauri/`), wired together by the app-layer source tree in
`src/`.

This README is a **runtime / data-flow / navigation map** for anyone (human or
agent) working in `src/`. The authoritative _rules_ live in
[`AGENTS.md`](../../AGENTS.md) and [`CONVENTIONS.md`](../../CONVENTIONS.md);
read those for the standards. This file tells you where things are and how
they connect.

---

## 1. The mental model

Four layers, dependencies flow downward only:

```
routes/       TanStack Router — exactly 2 top-level modes ("/" and "/onboarding")
app-shell/    Layout composition — the ONLY place cross-feature wiring renders
shared/       Cross-feature orchestration — the ONLY place to import 2+ features
features/     Business logic, one directory per domain (zero cross-feature imports)
packages/     Primitives + registries (no Tauri, no business state, no IPC)
crates/       Rust compute (searched from the backend)
```

The two rules that trip up most newcomers:

- **Features never import each other** — `features/{vault,tabs,editor,search,
settings,graph}` have no imports between them. If two features must talk,
  the wiring lives in `shared/` or `app-shell/`. The one exception is
  type-only imports via a feature's `types.ts`.
- **The shell renders from registries, not hardcoded imports** — new panels and
  leaves register in `app-shell/registrations.ts` (ADR-018). You almost
  never edit `app-shell/SideDock.tsx` or the tab rendering to add a view.

Each feature directory has an `index.ts` barrel — the only legal import
surface for other layers.

## 3. Boot flow

```
process spawn
  src-tauri/src/lib.rs::run()
    PROCESS_START anchor
    setup(): spawns "preboot" thread (full boot pipeline NOW, ADR-020)
             + "show-failsafe" (open window after 10s if never painted)

webview start
  main.tsx              ttiMark("js_entry")
  routes/index.tsx      loader: invoke<BootResult>("boot")
                          └─ the "boot" command BLOCKS on the preboot mutex
                             until run_preboot finished (never double work)
  Boot                  initSettings(boot.settings)  → seeds settings store
                        useTabPersistence()           → hydrates tabs from boot.workspace
                        → <Shell boot/>
  Shell                 AppProvider → useWorkspace
                        gates on vault present; else VaultSplash (pickAndSetVault)
```

TTI instrumentation (ADR-017) is spread across two sides:

- **Rust:** `BootResult.timings` (µs map) — `process_to_invoke`,
  `rust:vault_load_or_index`, `rust:search_init`, `rust:build_flat_tree`, …
- **Frontend:** `app-shell/tti.ts` — `ttiMark("js_entry" | "loader_start" |
"boot_resolved")`; `writeTtiReport()` merges both → `invoke("write_dev_report")`.

## 5. Frontend ↔ backend (Rust) seams

All IPC goes through `invoke(...)` (Tauri) against `src-tauri/src/lib.rs`
(29 commands). The important contracts:

- **`boot`** → `BootResult` (seed only — never stored globally).
- **`vault://file-changed`** event → external changes only, by contract. The
  editor reconciles via `reconcile.ts` (identity wins → ignore; clean →
  reload; dirty → conflict banner).
- **`open_file` / `save_file`** → autosave path: per-tab `saveManager` 2s
  debounce, flush on tab-switch/blur/unmount. Batched `save_files`/`open_files`
  variants exist for future Rust acceleration (ADR-007).
- **`get_workspace` / `set_workspace_key`** → tab persistence (400ms debounce
  on `persistVersion`), hydrated once at boot.
- **`rename_note` / `rename_path`** → `updateTabPaths` keeps stable tab ids so
  EditorState caches, undo history, and dirty state survive moves/renames.
- **Write contract (backend):** every app-initiated mutation registers
  self-write markers _before_ touching disk, updates vault cache + search index
  directly, and emits **nothing** — the frontend refreshes its own tree.

### Backend surface (`src-tauri/src/`)

```
lib.rs        PROCESS_START anchor + run() (builder, preboot, invoke_handler)
app_state.rs  AppState: vault, vault_path, watcher, search, self_writes (Arc-wrapped)
config.rs     Three-tier storage: config.json (global) / folder-hash.json (vault cache) /
              vault/.basalt/workspace.json (portable workspace)
watcher.rs    vault://file-changed emitter + search flusher
commands/
  boot.rs     PREBOOT OnceLock; phased, timed boot; set_vault (full index)
  files.rs    THE WRITE CONTRACT + open/save/create/delete/move/rename/autocomplete
  vault.rs    reindex_vault, get_vault_tree, open_vault_dialog, get_graph
  search.rs   search_content / search_files (Tantivy + Nucleo)
  settings.rs get_settings / set_setting / get_workspace / set_workspace_key
  frontmatter.rs  parse_frontmatter (backend twin of the in-editor WASM parser)
  dev.rs      write_dev_report → <tempdir>/basalt-reports/
```

## 6. Registries — the ADR-018 spine

| Registry            | Package file                     | Entries                                     | Rendered by                                   |
| ------------------- | -------------------------------- | ------------------------------------------- | --------------------------------------------- |
| `viewRegistry`      | `packages/views/src/registry.ts` | `file-explorer` (left), `backlinks` (right) | `app-shell/SideDock.tsx` (generic)            |
| `leafRegistry`      | `packages/views/src/leaf.tsx`    | `markdown`, `graph` (lazy)                  | tab content resolution in `Shell`             |
| `commandService`    | `packages/commands`              | editor/search/settings/tab commands         | `CommandProvider` + Ctrl+P UI                 |
| `keybindingService` | `packages/keybindings`           | `keybindings.json` rules + `when` clauses   | `KeybindingListener` (single window listener) |
| Settings sections   | `features/settings/store.ts`     | `registerSection` (plugin seam)             | `SettingsModal`                               |

**If you're adding a view or leaf:** register it in
`app-shell/registrations.ts`. That is the entire wiring step — the shell
renders whatever the registries hold.

## 7. Key entry points for an agent

| Task                              | Look at                                                                          |
| --------------------------------- | -------------------------------------------------------------------------------- |
| Add a sidebar dock / leaf         | `app-shell/registrations.ts` + `packages/views`                                  |
| Wire two features together        | `shared/` (never inside a feature)                                               |
| Trace a note open → editor → save | `shared/useWorkspace.ts` → `useEditor` → `logic/saveManager`                     |
| Understand the editor typing path | `packages/editor` (CM6 extensions) — **keep the keystroke path React-free**      |
| Add an IPC command                | `src-tauri/src/lib.rs` + `commands/*`; expose via a feature hook                 |
| Understand boot / TTI             | `app-shell/Boot.tsx`, `routes/index.tsx`, `app-shell/tti.ts`, `commands/boot.rs` |

## 8. Non-negotiables (quick list)

- Features never import each other (types-only via `types.ts` exception).
- No per-keystroke React re-renders in the editor — CM6 state is swapped via
  `view.setState()` on an uncontrolled host (`Host.tsx`).
- Batch `invoke()` calls; never N serial calls when one batched call works.
- Virtualize lists over ~100 items (`@tanstack/react-virtual`).
- Colors use `--sat-*` tokens only; no raw hex/Tailwind color classes.
- Comments: no banner/box dividers; state reasoning inline with ADR as a
  trailing footnote (CONVENTIONS §8).
