## What We're Building

A native, Rust-powered two-speed search system for Basalt:

- **`⌘O` Quick File Switcher** — instant fuzzy filename matching using `nucleo-matcher`, operates on filenames already in RAM
- **`⌘F` Full-Text Search Modal** — BM25-ranked full-text search using `tantivy`, with match highlighting, incremental index updates, and tag support

Both are modals. Both close after selection. Selecting a result opens the note in the current pane, scrolls to the first match, and highlights all matches in the editor.

## New Crate: `basalt_search`

Search logic lives in a new `crates/basalt_search/` crate. It depends on `basalt_core` and `basalt_fs` but not on Tauri — keeping it testable in isolation.

**Public API:**

```rust
pub struct SearchState {
    pub tantivy: TantivyIndex,
    pub nucleo: NucleoScorer,
}

impl SearchState {
    /// Open or create the tantivy index at `index_dir`.
    /// Run incremental reindex against the live vault mtimes.
    pub fn open_or_create(index_dir: &Path, vault: &Vault) -> Result<Self>;

    /// Full-text BM25 search. Returns ranked results with highlighted snippets.
    pub fn search_content(&self, query: &str, limit: usize) -> Vec<ContentResult>;

    /// Fuzzy filename search via nucleo scorer.
    pub fn search_files(&self, query: &str, limit: usize) -> Vec<FileResult>;

    /// Call when a note is saved. Removes old doc, indexes new content, commits.
    pub fn update_document(&mut self, path: &str, content: &str) -> Result<()>;

    /// Call when a note is deleted.
    pub fn remove_document(&mut self, path: &str) -> Result<()>;
}
```

## Tantivy Schema

```
Field    | Type | Stored | Indexed | Position | Boost
---------|------|--------|---------|----------|---------
path     | TEXT | yes    | yes     | no       | —
title    | TEXT | yes    | yes     | yes      | 3.0×
body     | TEXT | no     | yes     | yes      | 1.0×
tags     | TEXT | yes    | yes     | no       | 2.0×
```

- `body` is not stored (reduces index size). Snippets are generated by re-reading the raw file and using `aho-corasick` to find and highlight matches.
- `tags` contains space-separated tag tokens: both frontmatter `tags: [rust, notes]` and inline `#rust` (stripped of `#`).
- `title` is the filename stem (e.g. `borrow-checker` from `rust-notes/borrow-checker.md`), boosted to surface filename matches above body matches.

## Index Persistence

Index stored at: `<tauri app data dir>/search-index/<sha256(vault_path)[:8]>/`

**On app boot (boot sequence):**
1. `reindex_vault` runs (existing) — rebuilds `Vault` graph
2. `SearchState::open_or_create(index_dir, &vault)` — opens mmap index, diffs mtimes, re-indexes changed files
3. `AppState.search` set to `Some(Arc<RwLock<SearchState>>)`
4. Frontend receives `search-ready` event → enables search button + shortcuts

**On file change (watcher event):**
1. `basalt_fs` watcher fires `FileChanged(path)` / `FileDeleted(path)`
2. Tauri command handler calls `search_state.update_document()` or `remove_document()`
3. tantivy commits a new segment (background merge policy keeps query performance stable)

**Index location must be excluded from vault sync.** All index files live under `<app-data>`, not inside the vault directory.

## Tauri IPC Commands

### `search_content`

```
Input:  { query: string, limit?: number }  // default limit: 20
Output: ContentResult[]
```

```typescript
interface ContentResult {
  path: string;          // relative vault path
  title: string;         // note title (filename stem)
  score: number;         // BM25 relevance score (for debug display)
  snippets: Snippet[];   // up to 3 highlighted excerpts
}

interface Snippet {
  text: string;          // plain text excerpt (~120 chars)
  highlights: [number, number][];  // [start, end] byte offsets within text
}
```

### `search_files`

```
Input:  { query: string, limit?: number }  // default limit: 10
Output: FileResult[]
```

```typescript
interface FileResult {
  path: string;    // relative vault path
  score: number;   // nucleo alignment score
}
```

## Frontend Components

### `SearchModal` (⌘F)

- Opens as a centered overlay (same layer as command palette)
- Input field with debounce: 150ms after last keystroke → fires `search_content`
- Results list: title + path breadcrumb + up to 2 snippet previews with highlighted matches
- Loading state: spinner after 100ms if results haven't arrived (prevents flicker on fast queries)
- Keyboard: `↑↓` to navigate, `↵` to open, `⌘↵` to open in new tab, `Esc` to close
- Tag filter: typing `#rust` switches query mode to tag search (passes `tags:rust` to tantivy)

### `QuickSwitcher` (⌘O)

- Minimal modal — just a search input + filename list
- No debounce — fires `search_files` on every keystroke (nucleo is synchronous, sub-ms)
- Keyboard: same as SearchModal
- Displays path relative to vault root, filename stem bolded

### Result Opening

Both modals call the existing tab/pane open flow:
1. `openFile(path)` on the current pane
2. After file loads, editor scrolls to first match position
3. Editor decorations applied for all match ranges (cleared on next user edit or Esc)

## V1 Search Capabilities

| Capability | Engine | How |
|---|---|---|
| Full-text body search | tantivy | BM25 `TermQuery` / `PhraseQuery` |
| Typo tolerance | tantivy | `FuzzyTermQuery` (edit distance 1) |
| Filename fuzzy search | nucleo | Smith-Waterman alignment on arena strings |
| Tag search | tantivy | `tags:` prefix in query → field-scoped `TermQuery` |
| Match highlighting | aho-corasick | Scan matched doc body for query terms → byte offsets |

## Performance Targets

| Metric | Target | How achieved |
|---|---|---|
| Full-text search latency (5k notes) | < 150ms | tantivy BM25 over mmap index |
| File switcher latency | < 16ms | nucleo over RAM strings, no IPC round-trip needed beyond first load |
| Index build time (5k notes, cold) | < 2s | tantivy ~300GB/hour throughput |
| Incremental update (one file saved) | < 100ms | single segment commit, no full rebuild |
| Index disk footprint (5k notes) | < 50MB | body not stored, positions compressed |
